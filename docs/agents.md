# AI agents 指南

本文件是 AI agents 修改 RJ Warp Gate 时的规范入口。开始任务前还必须阅读：

1. [开发文档索引](README.md)
2. [目标架构](architecture.md)
3. [开发规范](development.md)
4. 与任务对应的 `docs/features/` 文档
5. 当前版本的 `docs/plans/` 文档

## 1. 文档边界

- 根目录 README 面向脚本用户，不是架构规格。
- `docs/architecture.md` 定义允许的依赖方向。
- `docs/development.md` 定义工程约束。
- `docs/features/` 定义功能语义和验收标准。
- `docs/plans/` 定义版本范围和交付顺序。

发生冲突时，优先遵循用户当前明确要求；然后是仓库中更具体、与任务更接近的功能规格；最后是通用开发规范。发现文档互相矛盾时，不应自行选择最方便的一项，应在变更中修正文档或向维护者说明。

## 2. 修改前

- 检查 `git status`，保留现有和无关修改。
- 搜索调用链和测试，不根据文件名猜测职责。
- 判断任务属于缺陷修复、架构迁移、用户功能还是文档维护。
- 明确是否会改变用户可见行为、GM 权限、网络目的地或网络请求数量。
- 如果改变网络行为，必须给出预算、触发条件、取消条件和失败退化方式。

## 3. 实现规则

- 新核心代码写入目标架构对应层级，避免继续扩大 `common/scraper.ts` 等旧聚合模块。
- 在核心解耦完成前，允许小型兼容适配器；必须标记移除里程碑，不能形成第二套永久 API。
- 不让 Preact 组件直接使用 GM 网络或存储全局变量。
- 不让通用控制器或 UI 直接依赖具体网站 Provider；新网站通过能力协议和 Registry 接入。
- 不为论坛中的每个 RJ code 创建 Preact Root。
- 不通过扩大 `@connect *` 或增加 grant 来绕过设计问题。
- 不把真实站点网络用作自动测试。
- 不在同一个变更中同时进行无关的视觉重设计和架构迁移。

## 4. 验证

根据任务运行最小充分验证：

- 文档：检查相对链接、版本状态和职责边界。
- 纯 TypeScript：相关单元测试、typecheck、build。
- Preact UI：组件测试、typecheck、build，并检查移动端/桌面状态。
- 网络或缓存：超时、错误、空结果、并发、force、旧响应和取消测试。
- DOM 扫描：大批量节点、重复 mutation、可编辑区域和原始链接语义测试。

如果仓库尚未具备目标命令，应在交付说明中明确哪些验证暂时无法自动完成，不能把 Vite 构建成功等同于类型检查或测试成功。

## 5. 文档同步矩阵

| 变更 | 必须检查的文档 |
| --- | --- |
| 模块边界或依赖方向 | `architecture.md` |
| 网络、缓存、预取或限流 | `development.md` 和对应 feature 文档 |
| 当前版本范围或里程碑 | 当前 `plans/v*.md`（现为 `plans/v1.3.1.md`） |
| 用户可见功能 | 三个根 README |
| AI 工作流程 | 本文件和根 `AGENTS.md` |

## 6. 当前版本特别约束

- v1.3.1 是基于 v1.3.0 架构的补丁版本，当前范围以 `plans/v1.3.1.md` 为准，不借机进行无关视觉重设计或架构迁移。
- DLsite 搜索结果列表必须从组件边界消除横向溢出，只保留长列表的纵向滚动；不得通过裁切整个宿主页面来掩盖问题。
- 长标题修复必须覆盖连续英文、URL/RJ 编号式不可断行内容及宿主样式干扰；仅缩小字号不能作为完整修复。
- v1.3.0 已建立的网络、缓存、权限和跨标签协调约束在补丁版本中继续有效。

- 补丁版本不得重新引入 Vue runtime 或绕过现有 Preact/控制器边界。
- South Plus RJ 预取最多选择两个候选，默认串行，并遵循功能规格中的网络条件。
- 预取只访问 DLsite 元数据端点，不触发 South Plus 搜索、ASMR ONE 查询或图片下载。
- 用户操作必须优先于预取，并复用同一查询的 in-flight Promise。
- DLsite 发起的 South Plus 搜索必须遵循跨标签 FIFO、10.5 秒启动间隔、60 秒等待上限和仅手动重试的功能规格。
